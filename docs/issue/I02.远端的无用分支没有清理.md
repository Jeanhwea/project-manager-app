## 具体疑问

为什么下面的无效分支没有清理？

```text
remotes/gitana/feat/LLM 可用性
remotes/gitana/feat/主页重组
remotes/gitana/feat/同步免打扰
remotes/github/feat/LLM 可用性
remotes/github/feat/主页重组
remotes/github/feat/同步免打扰
```

## 解决方案

根因：旧逻辑的 "E 类" 判定是**反的**——它只清理「远端存在但**未合并**到保护分支」的远端跟踪引用，
并且对已合并的分支直接 `continue` 跳过。所以这些已合并到 master/dev 的 `feat/*` 远端分支永远不会被清理。

修复（src/commands/branch.rs）：重新定义 **E 类 = 本地分支已删除 + 远端分支仍存在 + 已合并到保护分支**：

1. 遍历本地远端跟踪引用 `(remote, branch)`，依次过滤：
   - 跳过保护分支（master/dev/main/develop）；
   - 跳过本地仍存在的同名分支（那种归 C 类处理，本地删了才进 E 类）；
   - 远端必须真实存在该分支（`git ls-remote --heads` 校验，否则归 D 类孤儿）；
   - 必须已合并到某个保护分支（`git branch -r --merged <protected>` 校验），未合并的远端分支保留。
2. 命中后执行删除：`git push <remote> --delete <branch>` 清除远端分支 + `git branch -d -r <remote>/<branch>` 清除本地跟踪引用。
3. 汇总行改为 `E类远端已合并 N条`，并列出具体分支。

注意：清理前可用 `pma c --dry-run` 预览；远端不可达时只删本地跟踪引用、不发起必然失败的 `push --delete`。
