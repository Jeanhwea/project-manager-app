# 自动清理分支命令需求文档

## 概述

1. 重写 `pma br cl`（`pma branch clean`）命令，
   - 将之前"只保留 master/dev 及其别名、其余全删"的粗暴逻辑改为**基于分支分类的精细化清理**
   - 让开发者在日常清理时能安全操作，只删除那些已经没有保留价值的分支。
2. `pma br cl` 命令太长，简化敲  `pma c` 实现相同功能


## 分支分类体系

| 类别     | 定义                                           | 清理策略                 | 英文标识  |
|----------|------------------------------------------------|--------------------------|-----------|
| **A 类** | 保护分支（`master`、`main`、`develop`、`dev`） | 永不删除                 | Protected |
| **B 类** | 未合并到任一保护分支的分支                     | 默认保留，加 `-D` 时清理 | Unmerged  |
| **C 类** | 已合并到任一保护分支的非保护分支               | 始终清理                 | Merged    |
| **D 类** | 远端孤儿引用（本地残留、远端已删除的跟踪引用） | 始终清理                 | Orphan    |

### A 类 — 保护分支

- 定义：`master`、`main`、`develop`、`dev`
- 行为：无论传入什么参数都不会被删除
- 保护手段：在 `collect` 阶段直接过滤，不进入待删除列表
- 对应远端同名分支同样不删除

### B 类 — 未合并分支

- 定义：所有非保护、非当前分支中，未合并到任一保护分支的分支
- 判定方式：对**仓库里真实存在的每个保护分支**执行 `git branch --merged <target>`，取并集作为已合并列表；不在该列表中的即为 B 类
- 默认行为：**跳过**，仅打印提示信息
- `-D` 行为：同时将 B 类分支加入删除列表
- 远端同名分支：仅当 `ls-remote` 确认远端真实存在时才 `git push --delete`
- 已在其它 worktree 检出的分支（`git branch` 输出的 `+` 标记）无法删除，直接跳过

### C 类 — 已合并分支

- 定义：所有非保护、非当前分支中，已合并到任一保护分支的分支
- 判定方式：与 B 类相反——在已合并列表中的即 C 类
- 行为：**始终删除**，不受 `-D` 影响
- 远端同名分支：与 B 类同样先经 `ls-remote` 确认

### D 类 — 远端孤儿引用

- 定义：本地存在 `refs/remotes/<remote>/<branch>`，但 `git ls-remote --heads <remote>` 已查不到该分支
- 候选集来源：`git branch -r`（本地真实存在的跟踪引用），跳过 `<remote>/HEAD -> ...` 这类符号引用
- 行为：逐条执行 `git branch -d -r <remote>/<branch>`，只清理本地引用，不触碰远端
- 不使用 `git remote prune`：它会无差别删除包括保护分支在内的全部 stale ref，无法满足"保护分支跟踪引用永不删除"的安全底线
- 与本地分支是否存在无关：本地分支仍在时也清理其失效的跟踪引用，本地分支本身按 B/C 类规则处理
- `ls-remote` 失败（远端不可达）时无法判断，该 remote 的 D 类检测整体跳过并给出提示，不影响 B/C 类清理

---

## 容错约定

- 保护分支的本地分支与跟踪引用在任何情况下都不删除，远端已删除时仅提示
- 清理类操作彼此独立且幂等，单条失败（引用已不存在、远端拒绝等）只告警并继续，不中断同仓库后续清理
- 清理汇总在所有操作执行完之后输出，反映真实执行结果
