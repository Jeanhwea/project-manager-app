# 自动清理分支 `pma br cl` 命令需求文档

## 概述

重写 `pma br cl`（`pma branch clean`）命令，将之前"只保留 master/dev 及其别名、其余全删"的粗暴逻辑改为**基于分支分类的精细化清理**，让开发者在日常清理时能安全操作，只删除那些已经没有保留价值的分支。

---

## 分支分类体系

| 类别 | 定义 | 清理策略 | 英文标识 |
|------|------|----------|----------|
| **A 类** | 保护分支（`master`、`main`、`develop`、`dev`） | 永不删除 | Protected |
| **B 类** | 未合并到任一保护分支的分支 | 默认保留，加 `-D` 时清理 | Unmerged |
| **C 类** | 已合并到 `master` 或 `dev` 的非保护分支 | 始终清理 | Merged |
| **D 类** | 远端孤儿分支（本地没有跟踪分支的远端分支） | 始终清理 | Orphan |

### A 类 — 保护分支

- 定义：`master`、`main`、`develop`、`dev`
- 行为：无论传入什么参数都不会被删除
- 保护手段：在 `collect` 阶段直接过滤，不进入待删除列表
- 对应远端同名分支同样不删除

### B 类 — 未合并分支

- 定义：所有非保护、非当前分支中，未合并到 `master` 或 `dev` 的分支
- 判定方式：执行 `git branch --merged master` 和 `git branch --merged dev`，取并集作为已合并列表；不在该列表中的即为 B 类
- 默认行为：**跳过**，仅打印提示信息
- `-D` 行为：同时将 B 类分支加入删除列表
- 远端同名分支：同步清除

### C 类 — 已合并分支

- 定义：所有非保护、非当前分支中，已合并到 `master` 或 `dev` 的分支
- 判定方式：与 B 类相反——在已合并列表中的即 C 类
- 行为：**始终删除**，不受 `-D` 影响
- 远端同名分支：同步清除

### D 类 — 远端孤儿分支

- 定义：远端存在但本地没有对应跟踪分支的远端分支
- 行为：始终删除
- 注意：D 类分支没有本地分支，因此只删除远端

---

## 命令参数

```
pma br cl [OPTIONS]
```

| 参数 | 简写 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--remote` | `-r` | `<REMOTE>` | `origin` | 远端名称 |
| `--dry-run` | `-n` | `bool` | `false` | 仅模拟显示，不实际执行 |
| `--delete-unmerged` | `-D` | `bool` | `false` | 同时清理 B 类（未合并）分支 |

### 参数作用详解

- `--remote <REMOTE>`：指定远端名称，用于推删远端分支。如果当前仓库没有该远端，会自动回退到首选远端或第一个可用远端。
- `--dry-run` / `-n`：模拟执行，不实际删除任何分支。用于预览将要被清理的分支。
- `--delete-unmerged` / `-D`：**关键参数**。默认只删除安全的 C 类分支。加 `-D` 后风险扩大，也会删除未合并的 B 类分支，请谨慎使用。

---

## 安全保护机制

1. **当前分支保护**：无论当前分支属于哪一类（B 类或 C 类），都不在待删除列表中
2. **A 类保护**：`master`/`main`/`develop`/`dev` 四名硬编码保护，永不删除
3. **警告保护**：默认行为只删除 C 类分支，B 类分支需要显式 `-D` 才会清理，防止误删未合并分支
4. **远端保护**：A 类分支的远端同名分支同样不会被删除
5. **Dry-run 保护**：始终支持 `--dry-run` 预览删除内容，确认后再执行

## 执行流程

```
collect 阶段
  ├─ 收集所有本地分支
  ├─ 读取 git context（当前分支、所有分支列表）
  ├─ 执行 `git branch --merged master` 获取已合并到 master 的分支
  ├─ 执行 `git branch --merged dev` 获取已合并到 dev 的分支
  ├─ 取并集得到已合并列表
  ├─ 过滤当前分支和 A 类分支
  ├─ 候选分支中在已合并列表的 → C 类
  ├─ 候选分支中不在已合并列表的 → B 类
  └─ 扫描远端分支，找出 D 类孤儿分支

plan 阶段
  ├─ 如果有 C 类分支 → 创建"清理 C 类分支"阶段
  │    ├─ git branch -d <branch>
  │    └─ git push <remote> --delete <branch>
  ├─ 如果有 B 类分支 且加了 -D → 创建"清理 B 类分支"阶段
  │    ├─ git branch -d <branch>
  │    └─ git push <remote> --delete <branch>
  ├─ 如果有 D 类孤儿分支 → 创建"清理远端孤儿分支"阶段
  │    └─ git push <remote> --delete <branch>
  └─ 始终执行 git remote prune <remote>

execute 阶段
  └─ 按阶段顺序执行 plan 中的所有操作
```

## 输出信息示例

### 命令：`pma br cl`（默认，只有 C 类）

```
【清理 C 类分支】
  [DELETE] feature/login-page  (local)
  [DELETE] feature/login-page  (remote: origin)
  [DELETE] bugfix/header-style  (local)
  [DELETE] bugfix/header-style  (remote: origin)
【清理远端孤儿分支 (D类)】
  [DELETE] origin/stale-topic (remote)
【同步远端跟踪分支】
  [PRUNE] origin

【B 类分支（未合并）共 2 个，使用 -D 可清理】
  [SKIP]  experiment/new-api
  [SKIP]  fix/performance
```

### 命令：`pma br cl -D`（同时清理 B 类）

```
【清理 C 类分支】
  [DELETE] feature/login-page  (local)
  [DELETE] feature/login-page  (remote: origin)
  [DELETE] bugfix/header-style  (local)
  [DELETE] bugfix/header-style  (remote: origin)
【清理 B 类分支（未合并到 master/dev）】
  [DELETE] experiment/new-api  (local)
  [DELETE] experiment/new-api  (remote: origin)
  [DELETE] fix/performance  (local)
  [DELETE] fix/performance  (remote: origin)
【清理远端孤儿分支 (D类)】
  [DELETE] origin/stale-topic (remote)
【同步远端跟踪分支】
  [PRUNE] origin
```

### 命令：`pma br cl -n`（Dry-run，仅预览）

```
[C 类分支] feature/login-page (local + remote)
[C 类分支] bugfix/header-style (local + remote)
[B 类分支] experiment/new-api (使用 -D 可清理)
[B 类分支] fix/performance (使用 -D 可清理)
[D 类孤儿分支] origin/stale-topic (remote)
[将执行] git remote prune origin
```
